# Чого бракує фреймворку

Сюди пишеться те, чого не вистачило в `@altera/client` / `@altera/server` при роботі над
цим застосунком: відсутній компонент, невистачальний гак у базовому класі, команда, яку
довелося писати руками замість спільної.

**Запис не спиняє роботу.** Порядок такий: зафіксувати прогалину тут → зробити обхід у
застосунку → рухатися далі. Обхід — це код у `app/`, а не правка `vendor/`: те, що
лежить у `vendor/`, затирається наступним `deno install`, і зміна зникне мовчки.

Формат — один блок на прогалину, свіжі зверху. Головне не побажання, а **випадок**: що
саме будували, що не вийшло і чим обійшлися. Побажання без випадку неможливо ні оцінити,
ні перевірити, коли його закриють.

## Шаблон запису

### <коротка назва прогалини>

- **Дата:** РРРР-ММ-ДД
- **Де вилізло:** модель / екран / команда, над якими працювали
- **Чого бракує:** що саме фреймворк не вміє
- **Обхід:** що зробили натомість і скільки коду це коштувало
- **Яким міг би бути API:** одним прикладом виклику, якщо він очевидний
- **Терміновість:** блокує / незручно / дрібниця
