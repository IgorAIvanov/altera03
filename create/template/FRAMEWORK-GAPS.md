# Чого бракує фреймворку

Сюди пишеться те, чого не вистачило в `@altera/client` / `@altera/server` при роботі над
цим застосунком: відсутній компонент, невистачальний гак у базовому класі, команда, яку
довелося писати руками замість спільної.

**Прогалина спиняє роботу.** Порядок такий: спинитися → спитати → дочекатися явної
вказівки → зафіксувати прогалину тут → і тільки тоді обхід, якщо його дозволили. Правило
діє й в автоматичному режимі: «спитати нема в кого» означає зупинитися й винести питання
нагору, а не вирішувати самому. Обхід, зроблений без рішення, лишається назавжди — наступний
не відрізнить його від задуму й повторить.

**Записується підтверджене, а не перше враження** «фреймворк цього не вміє»: найчастіше
шуканий гак існує під іншим іменем або задача повернута не тим боком. Невірно записана
прогалина гірша за незаписану — вона з'їдає увагу того, хто розвиває фреймворк, на роботу,
якої не треба робити.

Дозволений обхід — це код у `app/`, а не правка `vendor/`: те, що лежить у `vendor/`,
затирається наступним `deno install`, і зміна зникне мовчки.

Формат — один блок на прогалину, свіжі зверху. Головне не побажання, а **випадок**: що
саме будували, що не вийшло і чим обійшлися. Побажання без випадку неможливо ні оцінити,
ні перевірити, коли його закриють.

## Шаблон запису

### <коротка назва прогалини>

- **Дата:** РРРР-ММ-ДД
- **Де вилізло:** модель / екран / команда, над якими працювали
- **Чого бракує:** що саме фреймворк не вміє
- **Обхід:** що зробили натомість і скільки коду це коштувало
- **Яким міг би бути API:** одним прикладом виклику, якщо він очевидний
- **Терміновість:** блокує / незручно / дрібниця
