# `<ui-attachments>` — список вкладень запису

Файли, прикріплені до запису: скани, рахунки, листування. Працює однаково для
документів і довідників — зв'язок тримає саме вкладення
(`owner_model` + `owner_id`), тому в моделі не потрібно ані колонки, ані
табличної частини.

```html
<ui-attachments
  owner-model="invoice"
  .ownerId=${item.id ?? ""}
  .label=${t("invoice.attachments")}
></ui-attachments>
```

## Запис має бути збережений

Файл зберігається одразу при виборі — окремо від моделі, тому потрібен id
власника. Поки `owner-id` порожній, компонент показує підказку «спершу
збережіть запис» замість кнопки: це чесніше, ніж черга незбережених файлів,
яку користувач втратить при закритті вкладки.

Список сам перечитується, коли `owner-id` з'являється або змінюється — після
першого `save` нічого викликати не треба.

## Атрибути

| атрибут | тип | за замовчуванням | опис |
|---|---|---|---|
| `label` | string | `""` | заголовок блоку (інакше «Вкладення») |
| `owner-model` | string | `""` | ключ моделі-власника |
| `owner-id` | string | `""` | id запису-власника |
| `disabled` | boolean | `false` | |
| `accept` | string | `*/*` | фільтр діалогу вибору |
| `max-size-mb` | number | `10` | перевірка розміру на клієнті |

## Події

`attachments-changed` — `{ count }` після додавання чи видалення. Потрібна,
якщо форма показує лічильник вкладень десь іще.

## Методи

`reload()` — перечитати список. Викликати вручну майже ніколи не потрібно:
компонент реагує на зміну `owner-id` сам.

## Що бачить користувач

Зображення показуються мініатюрою, решта — іконкою файлу. Ім'я — посилання на
завантаження (`Content-Disposition: attachment`). Видалення питає підтвердження
і видаляє вкладення остаточно, разом із байтами.

Деталі підсистеми — [docs/blob-subsystem.md](../../../docs/blob-subsystem.md).
