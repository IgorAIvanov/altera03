# `<ui-date>` — поле дати/часу з календарем

Заміна нативному `<input type="date">`: той показує дату у форматі локалі
браузера і не піддається налаштуванню (специфікація зберігає значення як
`yyyy-mm-dd`, а вигляд віддає ОС). `ui-date` малює текстове поле сам, тож
формат і склад показаних частин дати задає шаблон.

```html
<ui-date .label=${t("invoice.date")} .value=${item.invoiceDate}
         @value-changed=${(e) => this.setField("invoiceDate", e.detail.value)}></ui-date>
```

## Значення

`value` — **завжди ISO**: `YYYY-MM-DD` або `YYYY-MM-DDTHH:mm:ss` (для шаблона
без дати — `HH:mm:ss`). Це те, що приймає й віддає PostgreSQL, тож у схемі
моделі поле лишається звичайним рядком-датою. Форматування — суто рівень UI.

Порожнє поле → `value === ""` → у payload піде `""`, яке SQL перетворює на
`null` через `nullif(...)`.

## Формат

Атрибут `format` — рядок із токенів `YYYY` `YY` `MM` `DD` `HH` `mm` `ss`
і довільних роздільників. Набір токенів визначає, **яку частину** дати
показуємо і як поводиться календар:

| `format`           | Вигляд           | Календар            |
|--------------------|------------------|---------------------|
| `DD.MM.YY` (типово)| `20.07.26`       | сітка днів          |
| `DD.MM.YYYY`       | `20.07.2026`     | сітка днів          |
| `DD.MM.YY HH:mm`   | `20.07.26 09:05` | сітка днів, час зберігається |
| `MM.YYYY`          | `07.2026`        | сітка місяців, день = 1 |
| `HH:mm`            | `09:05`          | без кнопки календаря |

Готові значення — `dateFormat` з [`client/shared/datetime.ts`](../../shared/datetime.ts):
`date`, `dateFull`, `dateTime`, `time`, `month`. Змінити формат дат по всій
системі = змінити константу там.

## Ввід

Поле терпиме до того, як користувач набирає дату (шаблон `DD.MM.YY`):

| Набрано      | Результат    |
|--------------|--------------|
| `20.07.26`   | 20.07.2026   |
| `200726`     | 20.07.2026   — злитий ввід ріжеться за ширинами токенів |
| `20/07/26`   | 20.07.2026   — роздільник будь-який |
| `1.7.26`     | 01.07.2026   |
| `20.07`      | 20.07 поточного року — відсутні частини беруться з поточного значення поля |
| `20`         | 20 число поточного місяця |
| `31.02.26`   | порожньо — неіснуючої дати не буває |

Вхід у поле виділяє значення цілком — як у `ui-decimal`.

## Клавіатура

| Клавіша | Стан | Що робить |
|---|---|---|
| `Enter` | після набору | фіксує значення (розбір, канонічний вигляд), фокус лишається в полі |
| `Enter` | нічого не набирали (значення може бути й порожнім) | перехід до **наступного контрола** |
| `Enter` | календар відкритий | закриває його й фіксує, фокус лишається |
| `Esc` | — | закриває календар; якщо закритий — відкат до значення на вході. Esc, що щось зробив, далі не йде (у табличній частині не прибирає заразом новий рядок) |
| `F4` | — | відкрити / закрити календар |
| `←` / `→` | календар відкритий | курсор ±1 день (для `MM.YYYY` — ±1 місяць) |
| `↑` / `↓` | календар відкритий | курсор ±7 днів — рядок сітки (для `MM.YYYY` — ±3 місяці) |
| `PageUp` / `PageDown` | календар відкритий | курсор ±1 місяць (для `MM.YYYY` — ±1 рік); з `Shift` — ±1 рік |
| `Home` / `End` | календар відкритий | перше / останнє число місяця (для `MM.YYYY` — січень / грудень) |
| `Enter` | календар відкритий, нічого не набирали | вибрати дату під курсором, календар закривається |
| `Tab` / `Shift+Tab` | — | наступний / попередній контрол |

Два `Enter` підряд — навмисно: перший показує, як розібралася набрана дата
(`200726` → `20.07.26`), і помилка розбору видна, поки фокус ще в полі.

**Стрілки при закритому календарі нічого не роблять** — ні в полі форми, ні в
комірці, як і в решти контролів. Доти `↑`/`↓` зсували дату на день, і в
табличній частині це спрацьовувало разом із переходом таблиці на сусідній
рядок: дата мінялася там, куди людина вже не дивилася. Змінити дату з
клавіатури — набрати її або вибрати в календарі (`F4`).

**Курсор календаря — не значення.** Відкритий календар ставить курсор (рамка) на
значення поля або на сьогодні; стрілки рухають курсор і гортають сторінки за
ним, а значення не міняють — `Esc` закриває календар, нічого не записавши.
Записує лише `Enter` або клік. Фокус увесь час лишається в полі: календар —
popover без власного фокуса, і клавіші йому передає поле. Тому, поки календар
відкритий, стрілки й `Enter` не долітають до табличної частини — як і зі
списком пікера. Якщо ж у полі щойно набирали, `Enter` фіксує набране, а не
курсор.

**Кнопка календаря — поза Tab-чергою** (`tabindex="-1"`): `Tab` з дати веде до
наступного поля, а не на кнопку. З клавіатури календар відкриває `F4`.

`Enter` і `Tab` поводяться однаково в усіх полях набору (`ui-picker`,
`ui-date`, `ui-decimal`, `ui-select`) — зведення в [ui-picker.md](ui-picker.md#клавіатура).

## Атрибути

| Атрибут          | Тип     | Типово      | Опис |
|------------------|---------|-------------|------|
| `value`          | string  | `""`        | ISO-значення |
| `format`         | string  | `DD.MM.YY`  | шаблон показу й розбору |
| `label`          | string  | `""`        | підпис |
| `label-position` | string  | `top`       | `top` \| `left` |
| `placeholder`    | string  | = `format`  | підказка в порожньому полі |
| `disabled`       | boolean | `false`     | |
| `readonly`       | boolean | `false`     | ховає кнопку календаря |
| `required`       | boolean | `false`     | зірочка біля підпису: `?required=${this.isRequired("date")}` |
| `invalid`        | string  | `""`        | текст помилки: червона рамка + підпис під контролом ([ui-form-validation.md](../../../docs/ui-form-validation.md)) |
| `show-clear`     | boolean | `false`     | кнопка очищення в календарі |
| `size`           | string  | `""`        | `xs` \| `sm` \| `md` \| `lg` |
| `width`          | string  | `""`        | CSS-ширина обгортки |
| `cell`           | boolean | `false`     | режим комірки табличної частини |
| `visible`        | boolean | `true`      | |

> camelCase-властивості мають явний kebab-case `attribute` — інакше Lit
> зробив би `showclear`. Див. skill `lit`.

## Подія

`value-changed` — на комміт (blur / Enter / вибір у календарі),
`detail.value` — ISO-рядок або `""`.

## У табличній частині

```html
<td>
  <ui-date cell .value=${line.dueDate}
    @value-changed=${(e) => this.setLine(i, { dueDate: e.detail.value })}></ui-date>
</td>
```

`cell` вмикає контракт `.cell-control` із `client/styles/theme.css`:
контрол заповнює `<td>` цілком, рамку малює сама таблиця.

Стрілки `↑`/`↓` у комірці ведуть до рядка вище / нижче, як у решти контролів
табличної частини. Відкритий календар (`F4`) забирає стрілки собі, доки не
закриється.

## У списках

Колонка `ListColumn` має поле `format` — той самий шаблон:

```ts
{ key: "invoiceDate", title: "invoice.date", width: "7rem", format: dateFormat.date }
```

`ModelListBase` проганяє значення через `formatDate()`; нерозбірливе значення
показується як є.
