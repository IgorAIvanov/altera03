# `<ui-related-documents>` — пов'язані документи

Кнопка командної панелі форми документа і вікно з деревом: на які документи він
посилається, які посилаються на нього, і далі ланцюжком — від коренів униз, як
«Структура підпорядкованості» в 1С.

```ts
import "@client/ui-kit/components/ui-related-documents.ts";

protected override renderAuxActions() {
  return html`
    <ui-related-documents model="invoice" .documentId=${this.$root.item.id ?? ""}
      .routeOf=${(typeCode: string) => viewRoute(typeCode)}></ui-related-documents>`;
}
```

Дерево будує ядро — команда `related`, яку має кожен документ
(`app.document_related`, право `view`). Ребра — усі `x-ref` документа на документ
у шапці й табличних частинах, зібрані `sql:assemble` зі схем; відмова —
`"x-ref": { …, "related": false }`. Екран нічого для цього не оголошує.

## `routeOf` дає застосунок

Вузол приходить із кодом типу — ключем моделі. Маршрут форми з нього виводиться
через view-manifest, а його генерують манифести **застосунку**: фреймворк його не
бачить. Тому без `routeOf` дерево показується, але вузли не відкриваються.
Одне місце на весь застосунок зручніше за рядок у кожній формі — у altera03 це
`relatedDocumentsButton(model, id)` з `app/shared/related-documents.ts`.

## Що видно у вузлі

- значок стану (новий / проведений / позначений на видалення) — з назвою в
  `title`, тобто не лише кольором;
- подання документа (падіння — вид і номер), дата, сума;
- поточний документ — жирним і з позначкою, не відкривається;
- **повтор** — документ із двома батьками розкривається під першим, під другим
  лише згадується («показано вище»);
- **недоступний** документ (немає права `view` на його модель) — лише вид і
  «немає доступу»: реквізитів сервер не віддав. Прибрати вузол цілком означало б
  збрехати про те, скільки кроків між документами.

Вікно вдвічі ширше за типове (`min(92vw, 64rem)`), а подання документа
переноситься по словах: дата й сума видні завжди, гортати вбік не треба.
Гілка псевдографіки стоїть окремим стовпчиком рядка, тож перенесена назва
лягає під назвою, а не під лініями дерева.

Документ, ні з чим не пов'язаний, отримує пояснення словами, а не дерево з
одного рядка. Компонента, більша за межу (200 вузлів), показується найближчими
документами з приміткою.

## Атрибути

| атрибут / властивість | тип | за замовчуванням | опис |
|---|---|---|---|
| `model` | string | `""` | модель документа, чию команду `related` кликати |
| `document-id` | string | `""` | id документа; порожній — кнопка вимкнена («збережіть документ») |
| `disabled` | boolean | `false` | |
| `.routeOf` | `(typeCode) => string \| null` | `() => null` | маршрут форми за кодом типу |

Дерево перечитується на кожне відкриття: між двома відкриттями документ могли
пов'язати з іншим. Псевдографіку рахує чиста функція `treePrefixes`
(`client/ui-kit/related-tree.ts`, під пробою).
