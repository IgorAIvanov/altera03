# `<ui-file-dock>` — розділене вікно: файл і форма одночасно

Ділить панель вкладки навпіл: у одній половині вкладення (PDF, скан), у другій
— сама форма. Між ними смуга, яку тягнуть мишею; кожна половина гортається
окремо.

Задача — **звірка**: агент розпізнав скан і заповнив документ, людина порівнює
те, що вийшло, з тим, що прийшло. Порівнювати можна лише те, що видно
одночасно.

```ts
import "@client/ui-kit/components/ui-attachment-button.ts";
import "@client/ui-kit/components/ui-file-dock.ts";

protected override renderAuxActions() {
  return html`
    <ui-attachment-button owner-model="invoice" .ownerId=${this.$root.item.id ?? ""}>
    </ui-attachment-button>`;
}

override render() {
  return html`
    <ui-file-dock owner-model="invoice" .ownerId=${this.$root.item.id ?? ""}>
      ${this.renderForm(html`…поля…`)}
    </ui-file-dock>`;
}
```

Два компоненти, і обидва потрібні: кнопка стоїть у командній панелі й вирішує,
ЩО показати; док обгортає каркас форми й вирішує, ЯК. Вибраний файл їде від
кнопки до дока подією `ui-file-open` — кнопка не знає про розкладку, док не знає
про перелік вкладень.

## Два режими, і кожен про своє

Перемикач — у смузі заголовка; вибір запам'ятовується.

| режим | коли він виграє |
|---|---|
| **розділення** (умовчання) | звірка рядок за рядком: форма СТИСКАЄТЬСЯ до своєї половини й гортається окремо |
| **плавуче вікно** | «глянути, що це»: форма лишається цілою, вікно пересувають і міняють у розмірі |

Різниця не косметична, і саме тому режимів два. Вікно поверх форми не стискає
її, а **ховає**: коли табличну частину видно посеред сторінки, розсунути їх
неможливо — місця немає ні під вікно, ні під форму. Зате коли треба лише
впізнати файл, ділити екран навпіл дорожче, ніж відсунути вікно вбік.

Стани зберігаються **окремо**: положення смуги й порядок половин — своє,
геометрія вікна — своє. Тому перетяг вікна не переписує розкладку розділення, і
повернення в неї застає її такою, якою лишили.

## Кнопка

| | |
|---|---|
| вкладень немає | кнопка вимкнена — обіцяти дію, якої немає, гірше, ніж не показувати її |
| одне | відкривається одразу; меню з одного пункта — зайвий клік на кожному документі |
| кілька | випадне меню з іменами й розмірами: до накладної чіпляють і скан, і лист, і платіжку |

Перелік читається наперед (той самий запит, що робить `<ui-attachments>` — самі
метадані) і перечитується на подію `attachments-changed`, тож після додавання
файлу сусіднім списком кнопка оживає сама.

Якщо форму **не** загорнули в док, клік нічого не покаже — і скаже про це в
консоль: подія лишилася без відповіді. Мовчазної діри в налаштуванні тут немає.

### Атрибути

`<ui-attachment-button>`: `owner-model`, `owner-id`, `label` (інакше «Перегляд»),
`disabled`.
`<ui-file-dock>`: `owner-model`, `owner-id`.

## Що бачить користувач

- **файл угорі, форма внизу** — і навпаки, кнопкою ⇅ у смузі заголовка (тільки в
  розділенні). Вибір запам'ятовується разом із положенням смуги (`localStorage`,
  ключ із id користувача);
- **плавуче вікно** тягнеться за смугу заголовка й міняє розмір за кут; за край
  екрана його пускають, але не цілком — смуга заголовка лишається досяжною, бо
  вікно, затягнуте цілком, виглядало б як «зникло»;
- **смуга розділення** тягнеться мишею; жодна половина не стискається нижче
  120 px, а у низькому вікні ділиться навпіл;
- **PDF** малює вбудований переглядач браузера — сторінки, пошук, друк, масштаб;
- **зображення** має свій масштаб (− / вписати / +), який скидається при зміні
  файлу;
- **решта типів** — напис і кнопка завантаження: файл є, просто дивитися його
  треба в чомусь іншому;
- **доки файл не відкрито, дока не видно взагалі** — екран виглядає так само, як
  без нього.

## Межі

- **висота — умова роботи.** Док ділить те, що йому дали, тож `BaseUI` віддає
  формі панель вкладки цілком (`:host { height: 100% }`). Екран, який будує свій
  `render()` без каркаса, мусить сам подбати про прокрутку свого вмісту;
- **одне вкладення за раз.** Порівняти два файли поруч не можна — для цього
  потрібне третє поле, і такої задачі поки не було;
- **вкладення не редагується** — док лише показує. Додавання, перейменування й
  видалення лишаються в [`<ui-attachments>`](ui-attachments.md);
- **розділення тільки горизонтальною смугою** (верх/низ). Ліво/право не
  зроблено: у бухгалтерській формі поля йдуть у колонку завширшки `max-w-3xl`, і
  вужча половина ріже саме її;
- **вікно ховається разом зі своєю вкладкою** — в обох режимах. Скан чужого
  документа поверх чужої форми це готова помилка вводу.
